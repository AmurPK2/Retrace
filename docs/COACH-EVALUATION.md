# Local coach evaluation and practical limits

The coach receives one cutoff across quote, visible bars, drawing anchors/styles, selected C1/C2, plans and positions. HTF context is rebuilt at that cutoff. Earlier-trade review uses the saved original decision or a separately archived pending revision; the later outcome is not entry evidence. Instrument/session changes cancel outstanding requests. No chart or question is sent to a paid cloud model.

The reported bad rules — automatically using a 4H close as SL, or requiring all targets outside a candle range — have explicit regressions. Numeric claims are checked against stored/computed values, including sub-dollar instruments. Contradictions are repaired or replaced with a useful evidence explanation. The former 85-word rejection conflicted with the requested 100–180-word explanation and has been removed.

## Fixed evaluation collection

The collection uses English timeframe questions; an ambiguous Norwegian C1/C2/two-entry description; an explicitly marked real C1/C2 pair with two drawn entries; valid and invalid buy geometry under a written geometry-only rule; the two reported universal-rule errors; and a CPU-only factual candle observation. Cases distinguish rule compliance, order risk and later outcomes. Offline regressions also test no-future cutoffs, conflicting stop claims, missing data, pending edits and repeated immediate answers.

Hardware observed: Ryzen 5 9600X (6 cores / 12 threads), 32 GB RAM, Radeon RX 6700 XT with 12 GB VRAM through Vulkan. Qwen3.5-4B remains the default, 8,192 context and up to 640 reply tokens. Runtime/model downloads pin their revisions and SHA-256 digests. Automatic GPU loading and a real CPU inference were exercised; settings can disable the GPU.

The larger Qwen3.5-9B candidate was tested, not promoted. Non-thinking GPU responses took roughly 16–46 seconds and still invented requirements or needed fallback. Thinking responses took around 40–60 seconds; a CPU attempt timed out near 187 seconds. The 4B GPU sample was around 9–26 seconds; CPU observations were around 80–118 seconds. These are observed task samples, not throughput benchmarks or guaranteed response times.

Six final reference cases return in approximately 0.45–0.70 seconds because known timeframe, ambiguity, geometry and source-rule questions can be answered from computed evidence and the learning guide. **These are deterministic evidence replies, not successful model-inference benchmarks.** Their UI label says so. Broader model reviews remain experimental and may need a labelled saved-data fallback. A larger model did not reliably improve correctness on this hardware.

The checks do not prove every generated sentence correct. Geometry is not strategy validation, a good result is not a good decision, and no probability of profit is claimed. The user must define actual entry confirmation rules; missing references should be selected, not guessed. Challenge reasoning receives a bounded local-AI review in 0.3.2, with the limits described below.

First-run testing used an empty isolated profile. Pinned model/runtime downloads completed; real data downloads initially met provider throttling and then resumed to all 192 requested hourly slots. The successful resume took about 260 seconds, with a subsequent ready-state restart around 6 seconds. Total first-run time depends on network/provider availability. Replay remains usable independently of AI. Offline checks use already downloaded prices and model files.

## Challenge feedback in 0.3.2

Actual Qwen3.5-4B tests found that unconstrained tutor prose could mix scheduled periods with actual candles, praise reasoning the learner had not written, or return incomplete fields. That implementation was rejected. The shipped challenge tutor instead selects a verbatim answer excerpt and a task-appropriate coaching focus using a constrained response schema. The app verifies both selections and supplies reviewed explanation templates and its own arithmetic. Failed factual checks cannot be marked checked; open-ended checks remain unclear. The UI explicitly describes this division.

Tests cover a correct 16-period answer, an incorrect eight-period answer and a vague buy-because-green explanation. Snapshots whitelist answer-time facts and omit later outcomes, later prices and profit. Incorrect quotes, unsupported focus choices and conflicting assessments reject. Attempts and feedback survive session changes and restart; interrupted inference recovers factual feedback. This is useful tutoring, not certification of a strategy or universal factual reliability for the broader chart model.

## 16 November 2026 isolated coach/data finishing work

The new evidence ledger is computed from actual supplied candles, selected C1/C2, drawings and orders at one cutoff. It exposes exact named candle-level matches, per-entry cash risk, individual targets, aggregate risk, drawing/draft versus pending/fill counts, completed entry candles, and literal numbers from the user's written rule. Literal rule numbers are references, not a strategy parser or evidence that a condition passed. Missing SL/TP is explicitly incomplete even when optional order fields pass geometry validation. Context reduction and truncated rules are disclosed rather than silently described as complete.

Checks now catch missing-SL safety claims, invented pending/fill states, blanket approval with missing/truncated rules, omitted entry prices in a two-plan assessment, and named C1/C2 high/low/close/open values that disagree with their actual fields. These checks are deliberately bounded; matching a stored number anywhere is still not proof that every sentence relates it correctly. A generated repair actually confused C2 close with C2 high. Its raw draft is preserved; the final field check rejects that error. It is not reported as a successful model answer.

The single `Vurder oppsettet` action remains. Generic requests still use the existing automatic local Qwen3.5-4B model and existing GPU/CPU loading. No paid cloud route, new model, 9B experiment or hardcoded example lookup was added. Deterministic evidence explanations name each entry and its risk, distinguish strategy compliance from geometry and execution, and cannot use an eventual winner to certify the decision. UI provenance labels explicitly distinguish calculated explanations from model generation and saved-data fallback.

### Actual inference measurements and methodology

The six cases in `scripts/coach-holdout.ts` were frozen before implementation. They became the development collection when their failures were used to improve evidence and validators; they are **not** an untouched generalization test. Raw generations, intermediate evidence-only generations, final production-budget generations and a real generated repair probe are saved separately. No deterministic reply is counted as model success.

The final production-budget GPU development samples took **5.00–8.55 seconds** for one raw generation each. The separate two-plan probe took **9.55 seconds**, followed by **8.93 seconds** for one actual generated repair; the repaired prose still made a false candle-field claim. One real CPU sample took **27.13 seconds** and still proposed an unjustified C1 marking. These are text-evidence requests (including drawing anchors and computed candle facts), **not image/vision benchmarks**, packaged UI timings, or full request/retry latencies. Runtime was existing llama.cpp b12374, existing Qwen3.5-4B Q4_K_M, 8,192 context, six CPU threads, temperature 0.3, seed 71 and at most 640 output tokens. GPU used Vulkan; CPU used zero GPU layers. There was no model search or download.

Final-validator rechecking accepts only two of those six raw development replies without an automatic issue. **This is not a 2/6 factual correctness score**: manual inspection found unsupported trend claims, confused execution status, poor Norwegian terms and misleading comparisons even among otherwise numeric-grounded replies. Conservative checks may also reject useful prose. Repair/fallback remains necessary; robust free strategy reasoning is still experimental. No claim of profitability, certified strategy validation or universal reliability is justified.

A separate four-case collection in `scripts/coach-blind-holdout.ts` is withheld from production/prompt tuning. It covers a confirmed two-sell plan, missing-SL EURAUD, invalid NAS100 CFD protection and an unmarked ambiguous C1/C2 pair, with expected explanations recorded before generation. The pilot had stale derived fixture fields after instrument scaling; only fixture chartScan/account/proposal were corrected before scoring, and pilot outputs are retained but excluded. Production code and prompting were unchanged after the held-out collection was introduced. Results and the manual audit are recorded in the finishing handoff; this small collection cannot establish general reliability.

Reproduce raw probes with `node --import tsx scripts/eval-coach.ts NAME --production-context`; add `--blind`, `--cpu`, or `--repair --case=two-plans` as required. Set `RETRACE_COACH_ASSETS` to an existing matching runtime/model folder and optionally `RETRACE_COACH_EVIDENCE` to a project-local output folder. The runner starts a hidden, isolated loopback server on a fresh local port, uses artificial test fixtures and stops only its own child. It never opens user sessions. `audit-coach-eval.ts FILE.json` rechecks saved raw prose using current validators; this is explicitly labelled revalidation, not fresh inference.

Finishing evidence: `F:/Projects/Retrace/artifacts/finishing-20261116/coach/evidence/` (development JSON, CPU/GPU runtime logs, frozen holdout inputs, raw generated repair, validator audits, build and test logs). Earlier measurements in this document are historical results from other tasks, not freshly repeated results here.

Final held-out result: four corrected-fixture raw GPU replies took **6.53–7.40 seconds** each. Only **one of four** passed the automatic checks; strict manual factual review passed **zero of four**. The automatic pass (missing-SL EURAUD) still invented a pending order and a negative R:R. The sell case reversed the arithmetic comparison (2035 described as above 2036); the NAS100 case invented a replacement stop; the ambiguous case fabricated pending orders. Useful partial observations do not turn these into correct overall assessments. This is direct evidence that **general free coach quality remains unresolved** and the validator is incomplete. No production prompt or model changes were made after seeing these holdout answers.

The pure deterministic renderer for those four held-out contexts took **0.07–0.62 milliseconds**, excluding IPC, data-quality reads, UI work and model loading. It is generic computed evidence rendering, not a matching lookup for these examples. Do not compare that number with user-perceived full response latency or count it as model inference. The corrected frozen inputs, raw outputs, expected explanations and strict manual failure reasons are in `blind-inputs-corrected-frozen.json`, `blind-corrected.json` and `blind-manual-audit.json` in the finishing evidence folder.
